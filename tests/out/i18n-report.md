## Hot language switch

On the game page, `bz-lang` calls `BZ.apply` (so `[data-i18n]` and `[data-i18n-aria]` update), then `renderOverlay`, `renderHud`, and `renderBitcoinCountry`. The ready menu, perk picker, pause menu, and versus lobby are rebuilt. A static arc card re-reads `body` / `bodyEs` on that rebuild. Cards whose body was filled when the card was dealt stay in that language until the next card: a job card, a chess card (`input === "move"` or id `chess`), and ids `anOffer`, `ambassador`, `firstBloc`, `rearmament`, `threeColors`, `blocReplies`, `blocAssault`, `battleWon`, and `blocTriumph`. The pause button aria-label is set in `renderHud` from `t("ariaPlay")` / `t("ariaPause")`. The HUD caption changes on the next `say()`; the line already on screen stays until then. An award toast that is already visible keeps the language it opened in (about 3 seconds). An auth error returned by the server stays as the server sent it. `chart.html` and `profile/index.html` listen for `bz-lang` on that same document and refresh the document title. `about/index.html` updates any `data-i18n` node if `setLang` runs there. `u/index.html` paints its headings, the missing-player lines, and owned awards from the language at load. A switch on the game page does not rewrite any other document until that document loads again.

## Voseo

The scan uses Unicode letter boundaries on every extracted string and on HTML text. It looks for vos, sos, vosotros, podés, tenés, querés, sabés, hacés, decís, venís, andá, decime, fijate, poné, vení, salí, tené, acordate, mirá, hacé, llegá, esperá, tocá, jugá, seguí, probá, decí, and elegí (not the standard preterite "yo elegí"). A hit is an error above. Infinitives such as poner + te + los do not match.

## What this does not prove

Layout at 390 px is checked in the browser, not here. Speech stays English on purpose; this report checks the visible caption. Identical glossary terms are listed as exceptions, not as translations.
